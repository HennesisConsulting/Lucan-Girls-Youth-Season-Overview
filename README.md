# Lucan Utd Youths — Web Output (auto-publishing setup)

Every time you upload an updated `Season_Data_Collection.xlsx`, the site
rebuilds and republishes itself automatically — usually within 1–2 minutes.
Nobody needs to touch HTML, JSON, or code.

**Everything you touch lives flat in the repo root.** There's nothing to
navigate into, nothing to get the path wrong on. The only two folders in
this repo — `docs/` and `.github/workflows/` — are ones you never manually
upload into: `docs/` is auto-generated by the build every time, and
`.github/workflows/` is a GitHub requirement, not something either of us
chose.

**A note on privacy:** GitHub Pages sites are publicly accessible to anyone
with the link — there's no password option on the free plan. The build
strips out specific injury/absence reasons (players show as "Unavailable"
only, never the detail), and the site is marked so search engines won't
index it. But the link itself isn't private, so only share it with people
you're comfortable having access.

## If you're migrating from the old folder structure

You had `workbook/`, `template/`, and `scripts/` subfolders before — this
version removes all three. To switch over on your *existing* repository:

1. Upload these four files directly to the **repository root** (not into
   any folder): `Season_Data_Collection.xlsx`, `dashboard_template.html`,
   `build.py`, and this `README.md`. Overwrite `.github/workflows/deploy.yml`
   with the new one in this package too (same path as before, just updated
   content).
2. Once that upload succeeds and the Actions tab shows a green run, delete
   the old `workbook/`, `template/`, and `scripts/` folders (see "removing
   old files" — press `.` on your repo's page to open github.dev, select
   the three folders in the file tree, delete, and commit).
3. Don't delete anything until step 1's build has gone green — that way
   there's no gap where neither the old nor new file locations are complete.

From then on, use the steady-state instructions below.

---

## Updating the data from now on

1. In Excel, make your changes and **save** the workbook
2. On your repository's main page (no folders to open), click
   **Add file → Upload files**, drag in the saved `.xlsx`, and click
   **Commit changes** — this replaces the old file automatically since it's
   the same filename in the same place
3. Wait 1–2 minutes — the **Actions** tab will show a build running, then a
   green checkmark. Refresh your live link to see the update.

That's genuinely it. No folders to pick, no way to drop it in the wrong
place — the upload button on the repo's main page *is* the right place.

**Note:** the build automatically forces Excel to fully recalculate before
reading it, so you don't need to press F9 before saving, though it doesn't
hurt to.

---

## If something goes wrong

Check the **Actions** tab — click the failed run (red ✗) to see exactly
what the build script printed. The most common causes:

- **"no .xlsx file found"** — the workbook needs to sit directly in the
  repo root, not inside any folder
- **"workbook has no sheet named 'Web Output'"** — the uploaded file isn't
  the right workbook, or that sheet got renamed/deleted
- **"cell A4 does not contain valid JSON"** — open the workbook, go to the
  Web Output sheet, and press F9 (or Ctrl+Alt+F9) to force Excel to
  recalculate before saving

If nothing seems to trigger automatically after an upload, go to
**Actions → Rebuild and publish Web Output → Run workflow** to force a
build regardless of what triggered (or didn't).

## Files in this repository

| Path | What it's for |
|---|---|
| `Season_Data_Collection.xlsx` | The source file — replace this whenever data changes |
| `dashboard_template.html` | The page design. Only touch this if you want the look changed |
| `build.py` | Reads the workbook, redacts sensitive fields, builds the page |
| `.github/workflows/deploy.yml` | Tells GitHub to run the build automatically |
| `docs/index.html` | The actual published page — generated automatically, don't edit by hand |
| `docs/robots.txt` | Keeps the page out of search engine indexes |
